# ADR-0006 — Harness Adapters are Projection Boundaries

Status: Accepted

## Context

Forge workflows execute inside coding Harnesses, but Harnesses expose materially different primitives such as persistent instructions, commands, skills, hooks, agent roles, and generated configuration.

ADR-0005 established that Harness Adapters consume Effective Forge Configuration and do not participate in semantic resolution. CHG-0002 must additionally decide how Adapter output is planned, owned, persisted, and safely published without allowing Harness-native artifacts to become an alternate source of Forge truth.

## Decision

Harness Adapters are projection boundaries.

An Adapter consumes resolved Effective Forge Configuration plus explicit repository/Harness state and produces a deterministic, human-reviewable `AdapterPlan` before mutation.

The plan is separated from publication. Core planning remains Harness-agnostic and mutation-free. A Safe Publisher may apply only conflict-free operations whose paths and ownership evidence have been validated.

Generated artifacts use explicit ownership modes:

- `forge_owned` — generated by Forge and replaceable only while current content still matches recorded expected generated state;
- `user_owned` — never silently overwritten;
- `shared` — mutable only through an explicit deterministic merge strategy, otherwise conflict.

Adapter installation metadata is repository-native derived state under `.forge/adapters/<adapter-id>/`. It may record Adapter identity/version, Harness target, Protocol compatibility, generated artifact paths/digests, and explicit limitations. It must not duplicate canonical Change lifecycle state or become semantic authority.

Unsupported Harness capabilities and unenforceable Forge invariants are represented explicitly. An Adapter must not claim enforcement it cannot provide.

Adapter, Protocol, Schema, and CLI versions remain independently versioned.

## Consequences

Forge can support heterogeneous Harnesses without moving canonical semantics into Harness-specific files. Planning can be reviewed and tested independently from filesystem mutation. User modifications to generated artifacts become detectable drift instead of being silently destroyed.

The model adds installation metadata, digest tracking, conflict handling, and safe-publication complexity. Shared artifacts require Adapter-specific merge strategies. Some Harnesses may be unable to represent every Forge invariant and therefore cannot claim full enforcement.

The first real Harness Adapter remains a separate Change so that no specific Harness shapes this Core abstraction prematurely.
